## 3. Alvo

### 3.1 Rótulo de provedor único (#23)

Mapa estático no playground (o orquestrador não manda rótulo: `/admin/schema` só devolve `name`), em `src/lib` (código puro, sem I/O): `providerLabel(raw) → { id, label, description? }`.

- Chave: `raw.trim().toLowerCase()`. Cobre os ids, os aliases e o nome de classe do agno, para os três valores que chegam hoje (id gravado, alias, `model.provider` do agno) caírem no mesmo rótulo.
- Valor desconhecido (plugin novo): rótulo = o valor como veio, sem descrição. Nunca quebra, nunca esconde.

| id gravado | Também chega como | Rótulo | Descrição curta no dropdown (pt-BR / EN) |
|---|---|---|---|
| `ollama` | `Ollama` | Ollama | (sem) |
| `openai` | `OpenAI` | OpenAI | (sem) |
| `anthropic` | `Anthropic` | Anthropic | (sem) |
| `gemini` | `Google` (agno), `google` | Google Gemini | "Id principal do Gemini, da Google." / "Main id for Google Gemini." |
| `google` (alias) | `Google` | Google Gemini | "Apelido de `gemini`: é o mesmo provedor." / "Alias of `gemini`: the same provider." |
| `groq` | `Groq` | Groq | (sem) |
| `azure` | `Azure` (agno) | Azure OpenAI | "Id principal do Azure OpenAI." / "Main id for Azure OpenAI." |
| `azureopenai` (alias) | `Azure` | Azure OpenAI | "Apelido de `azure`: é o mesmo provedor." / "Alias of `azure`: the same provider." |
| `openai_compatible` | `OpenAI` (agno, via `OpenAILike`) | Compatível com OpenAI / OpenAI-compatible | "Servidor próprio com API no formato da OpenAI." / "Your own server with an OpenAI-format API." |

O mesmo rótulo vale para id e alias de propósito: o critério do item é "o mesmo provedor com o mesmo rótulo nas três telas". O que diferencia `gemini` de `google` é o id (mostrado em mono no dropdown) e a descrição.

**Formato de exibição** (um só, recomendado em D-QA1-11-2): `Rótulo · modelo`, o rótulo em fonte normal (`text-foreground`/herdado) e o modelo em `font-mono`, separador `·` em `text-muted-foreground`. Ex.: `Google Gemini · gemini-2.0-flash`. Mesmo trecho nas telas:

| Tela | Alvo |
|---|---|
| Playground (`EntitySelector`) | 2ª linha do trigger: `Google Gemini · gemini-2.0-flash` (`text-xs text-muted-foreground`, `truncate`, `title` com o mesmo texto) |
| Lista de Agents (coluna Modelo) | mesmo trecho, `truncate`; o `title`/busca (`agent.id + SEPARATOR + modelOf`) continua com o id gravado para a busca achar `gemini` |
| Lista de Teams (`Chip`) | mesmo trecho dentro do `Chip` existente |
| Dashboard (Modelos de IA e de embedding) | título = modelo (como hoje); subtítulo `text-sm text-muted-foreground` = **só o rótulo** do provedor (o modelo já está no título; repetir poluiria) |

Todas as telas usam a mesma função `providerLabel`; o trecho `Rótulo · modelo` é um único componente de apresentação (`ProviderModel`), usado nas três telas com modelo (Playground, Agents, Teams): são 3 usos reais.

**Dropdown de provedor** (`ModelSection`, e `ragProvider` do embedder se o schema trouxer pares): cada `SelectItem` com, nesta ordem:

```
Google Gemini   gemini            <- ItemText: rótulo (font-medium) + id (font-mono text-xs text-muted-foreground)
Id principal do Gemini, da Google. <- descrição, text-xs text-muted-foreground (só na lista, só se houver)
```

- O `SelectPrimitive.ItemText` envolve só rótulo + id, então o **trigger fechado mostra `Google Gemini gemini`** (rótulo + id) e a descrição só aparece na lista aberta. O valor gravado continua o id (`value={name}`): nenhuma mudança de contrato nem de payload.
- Lista (`SelectContent`) mantém a ordem do schema; item com descrição tem 2 linhas, sem descrição 1 linha (altura natural, sem `min-h` forçado).
- Valor gravado que o schema não lista mais (`withCurrent` já acrescenta): aparece com o rótulo do mapa ou cru, sem descrição.

### 3.3 Início (#27)

Cada card de passo: `CardHeader` com linha `flex-col gap-4 lg:flex-row lg:items-center` como hoje (ícone + título/descrição à esquerda, `flex-1 min-w-0`). Coluna de ações à direita:

```
lg (>= 1024):                                           celular (< 1024):
+----------------------------------------------+        +------------------------+
| (ico) Passo 1 · Crie seu primeiro agente     |        | (ico) Passo 1 ...      |
|       Configure um agente IA com …            |        |       descrição        |
|                              [ Criar agente →]|        | [ Criar agente →     ] |
|                              [ Marcar feito  ]|        | [ Marcar como feito  ] |
+----------------------------------------------+        +------------------------+
```

- **Coluna fixa**: `flex w-full flex-col gap-2 lg:w-52 lg:shrink-0`; os dois botões com `w-full justify-center` (largura 208 px em `lg`, a do card em celular). O 1º (link, `Button` padrão com `ArrowRight`) e o 2º (`variant="outline"`, "Marcar como feito"/"Desfazer") ocupam sempre as mesmas duas posições: **o x esquerdo e o direito dos botões são idênticos nos três cards** (a coluna tem largura fixa e termina em `padding-right` do card).
- **Estado feito**: a coluna **não desmonta**. O 1º botão continua (o passo concluído ainda pode ser revisitado: "Criar agente" etc.); o 2º vira "**Desfazer**" (mesmo `outline`, mesma posição e tamanho; sem ícone novo). Clicar em "Desfazer" volta o passo a pendente (`completed: false`), foco no próprio botão (que vira "Marcar como feito"); clicar em "Marcar como feito" mantém o foco no botão (que vira "Desfazer"). Nenhum diálogo (a ação é reversível, não destrutiva).
- **Altura do card estável**: a altura em `lg` é a da coluna de ações (2 × `h-10` + `gap-2` = 88 px) e não muda entre pendente/feito. Em celular o texto de descrição reserva 2 linhas (`min-h-8` em `text-xs`) nos dois estados, e a borda muda só de cor (`border-success`, sem trocar a espessura). Título riscado (`line-through`) e descrição "Concluído!" não alteram a altura do bloco.
- O texto de estado concluído continua `text-success`; `aria-live="polite"` numa região `sr-only` no `Card` anuncia "Passo N: concluído" / "Passo N: pendente" (a barra de progresso e o chip "N de 3 concluídos" já mudam; o leitor de tela hoje não ouve nada).
- Sem cor, token ou ícone novos. `Marcar como feito` mantém o texto de hoje; só `Desfazer` é texto novo (EN: "Undo").

### 3.4 Aba "Team" desabilitada (#28)

- Sem teams, o botão "Team" (e, simétrico, "Agente" sem agentes) deixa de ser `disabled` nativo e passa a `aria-disabled="true"` com `onClick` ignorado; continua na ordem de tab. Visual de hoje (`opacity-50 cursor-not-allowed`), `aria-pressed` conforme o modo.
- Envolvido pelo `Tooltip` existente (`src/components/ui/tooltip`, Radix), `side="bottom"`: abre no **hover e no foco** (teclado); some com Esc ou ao sair. Texto: pt-BR "Crie um team primeiro" / EN "Create a team first" (Agente: "Crie um agente primeiro" / "Create an agent first"). O trigger do tooltip é o próprio botão (sem wrapper extra que quebre o `grid grid-cols-2`).
- Acessibilidade: o `Tooltip` do Radix liga `aria-describedby` ao conteúdo enquanto aberto; além disso o botão desabilitado recebe `aria-describedby` apontando para um `<span class="sr-only">` com o mesmo texto, para o leitor de tela ouvir o motivo sem abrir o tooltip.
- Em toque não há hover e o tooltip do Radix não abre no tap: o motivo fica só no `sr-only`. Não é coberto por esta spec (limitação anotada; resolver seria um texto visível fixo, que é variação visual nova).

## 7. Acessibilidade

- Dropdown: rótulo "Provedor" já associado ao trigger (`htmlFor`); cada item tem nome acessível "Rótulo id" e descrição legível (ItemText + texto da descrição na linha seguinte); setas/Enter/Esc do Radix.

- Contraste AA: só pares de tokens já aprovados (`text-muted-foreground` sobre `bg-card`/`bg-background`; `text-success` sobre `bg-card`).
