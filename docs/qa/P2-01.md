## Lacunas e observações

- Boot real sem env (`next start` sem variáveis) não testado: o README já documenta que no `start` a validação ocorre na 1ª requisição; coberto por unit do `register()`.
- Fragilidade do e2e (não é bug): os logins do e2e dividem o IP real e o limite é 5 com reserva também no sucesso. Hoje 4 logins pela tela correm em paralelo mais o setup e passam; um novo spec com 2+ logins pela tela em paralelo pode estourar. Spec novo deve usar o storageState ou `mode: 'serial'`.
- Sem proxy que grave X-Forwarded-For, o cliente escolhe o IP (confirmado no e2e: o header forjado basta para um balde novo). Risco aceito e documentado no README.
- Contraste/corte em 390 px e alturas 36/44 px (V-10, V-13): design QA.
