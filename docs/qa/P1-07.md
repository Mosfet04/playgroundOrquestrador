| Modo | Teste mais lento |

| DEPOIS, 2 CPUs com 8 workers | mesmo teste, 21,3 s (limite do teste: 30 s) |
| Dev atual (15 s/5 s, 90 s) | "nenhuma rota rola..." (24 s, dentro dos 90 s) |

Risco: o tempo de teste (não o de uma asserção) chega a 6,8 s no prod com 8 workers, então nenhuma asserção individual fica perto dos 5 s. Um runner de 2 vCPU leva o Playwright a escolher 1 worker, e nesse caso o pior teste foi de 2,9 s, com folga grande. O cenário superalocado (2 CPUs, 8 workers) passou, mas com os testes lentos em ~21 s dos 30 s: só aconteceria se alguém forçasse `--workers` alto na CI. Vale ficar atento quando a suíte crescer.

## Limitações

- **D-P1-07-3 = A:** no prod o React não compara atributos, então a falta de `suppressHydrationWarning` no `<html>` (aviso do `class` do next-themes) não é detectável na CI. Só o e2e local (dev) pega. Não criei teste, como decidido.
- **Confirmação no GitHub Actions pendente:** o "5× verde na CI" foi validado simulando a CI localmente (D-P1-07-1 = A). Os tempos do Actions só saem do push do usuário.
- **Runner com 2 vCPU:** simulado com `taskset -c 0,1`, que não é equivalente ao Actions (CPU mais fraca, I/O e cache de disco diferentes).
- O `theme.spec` com `pageerror`/`#418` só pega texto divergente no prod. Não foi exercitado com uma divergência injetada, porque seria alterar código de produção.
