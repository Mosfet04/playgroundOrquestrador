## Observações (severidade baixa, sem decisão pendente)

- **OBS-1** `parameters[].default_value` é `z.unknown()`: aceita qualquer JSON, inclusive chaves `$`. Hoje é dado inerte (nenhum filtro o usa). Se a API Admin ou o Mongo recusar chave `$`, o erro vira 500. Fica para a P3.
- **OBS-2** A mensagem de erro cita o caminho com o nome da chave de `headers` (`headers.X-Chave`): é nome, nunca valor.
- **OBS-3** Se qualquer página de `/api/tools` falhar, o `AgentForm` descarta a lista inteira (tudo ou nada), sem aviso. A seleção prévia do agente vem de `agent.tools_ids` e segue no estado, mas sem a lista o usuário não vê o que está marcado. Sem teste.
- **OBS-4** `POST /api/tools` aceita `id` só com espaços (id opcional, sem `trim().min(1)`; o de agent exige). Qualidade de dado, não segurança.
- **OBS-5** (a11y, pré-existente) O rótulo "Tipo" do parâmetro não está associado ao Select (`Label` sem `htmlFor`), então o combobox não tem nome acessível. O teste o acha pelo bloco do rótulo.

## Lacunas / pendências

- Sem Mongo real: o escape do `$regex`, `$`-chaves em `default_value` e o `undefined` no `$set` (`rag_config`) foram verificados só contra o fake em memória. Cobertura real só quando a API Admin (P2/P3) substituir essas rotas.
- Cortado por proporcionalidade (rotas saem na P3), sem bug conhecido: PUT hostil de agent e de tool, `rag_config` no PUT, busca combinada com `active`/`factoryIaModel`/`method`, `route` inválida em outras formas, bordas de `isValidUrl`/`constructEndpointUrl`, falha da 2ª página do `AgentForm`, `route` com credencial (sai em claro, como os headers; fica para a P3-03).
- Fora de escopo, conforme o item e a revisão: `limit=0`/`NaN` em `page`/`limit`, id sem `encodeURIComponent` no cliente, auth (P2-01), mascarar headers (P3-03), migração de documentos com `number` (contagem abaixo).
- Não há e2e que cubra estas rotas (o fake orchestrator não fala com o Mongo); o item não exige.

## Pendência do usuário: tools legadas com `number`

O orquestrador não carrega tool com parâmetro `number` (`ParameterType["NUMBER"]` ⇒ KeyError). Contar no `mongosh`, no banco do orquestrador; se houver documentos, a migração é decisão do usuário:

```js
db.tools.countDocuments({ parameters: { $elemMatch: { type: { $regex: '^number$', $options: 'i' } } } })
```
